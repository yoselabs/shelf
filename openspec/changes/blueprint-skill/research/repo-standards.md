## 2. Field mapping — blueprint checkpoint vs shipped formats

| blueprint (design.md principle 2) | Scorecard probe `def.yml` | repolinter rule | Best Practices criterion | gap for blueprint |
|---|---|---|---|---|
| `id` | `id` | rule key | criterion id | — |
| `check` | `short` | `rule.type` + options | criterion text | — |
| `why` | `motivation` | `policyInfo` / `policyUrl` | — | — |
| `evidence` | — | — | `{Met URL}` / justification | blueprint's is the rule's evidence; Best Practices also wants **per-run** evidence (URL) for "met" |
| `verify` | `implementation` | the engine | — | — |
| `who decides` | — | — | — | blueprint-only |
| `applies to` | `ecosystem.languages`, `clients` | `where` axioms | `{N/A allowed}` | — |
| `fix` | `remediation.text/markdown` + `metadata.patch` | `fix` | — | **`effort`** (Scorecard: Low/…) |
| `expires` | `lifecycle: experimental \| stable` | — | — | **`lifecycle`** separate from expiry |
| verdicts | True / False / NotAvailable / NotApplicable / Error | pass / fail / warning | Met / Unmet / N/A / `?` | **"could not check"** verdict |
| override + reason | `scorecard.yml` annotation, fixed reason codes | `level: off` | N/A justification | **fixed reason codes** |

Reading: the template is already near-isomorphic to Scorecard's probe file. The fields others carry that
blueprint lacks are `effort`, `lifecycle`, a "could not check" outcome, and closed reason codes.

## 3. What goes wrong (across sources)

- **Existence ≠ effect.** Factory: criteria "mostly file-existence checks"; Scorecard: branch protection
  enabled with no real review. Same failure principle 4 names.
- **Thresholds and averages hide failures.** Factory's 80% gate; agentready's weighted 72.5/100;
  Scorecard's 0–10 aggregate. Only all-or-nothing levels (Cortex, OpsLevel, Soundcheck) say which
  check failed without opening the detail.
- **Self-attestation as evidence.** Best Practices "Met + justification"; MS checklist ticks.
- **Unverifiable checks.** MS ">90% if possible" has no command.
- **Engines and fixers rot.** repolinter archived; agent-harness (prior-art.md) stalled the same way.
- **Instruction files bloat.** OpenAI [S], Claude Code docs, ETH [S]: generated or long context files
  cost tokens and success; content an agent can derive from code is noise.
- **Templates diverge.** Copier/cruft need a version pointer and a merge; projen avoids divergence by
  forbidding edits; Böckeler: harness templates inherit the same sync problem.
- **Heuristics misfire.** Scorecard false positives (systemd issue [S]); the fix is a recorded annotation,
  not code changes.

## 4. Verdicts for blueprint

1. ✅ **Add a fifth verdict: "not checked (reason)".** Scorecard separates `NotAvailable`/`Error` from
   NotApplicable; Best Practices has `?` distinct from N/A. Principle 3 today forces an unrunnable check
   (no token, no network, tool missing) into "failing" (false alarm) or "n.a." (false comfort). Not done,
   never counted as passing.
2. ✅ **Overrides use closed reason codes plus free text, checked in.** Take Scorecard's set as the
   start: `test-data`, `remediated`, `not-applicable`, `not-supported` (met another way), `not-detected`
   (met, the check missed it). Free-text-only reasons can't be audited or reconciled by kind. Where it
   lives is still F1 (Fable).
3. ✅ **Keep F5 as decided: binary per checkpoint, no averages, no thresholds.** Every scored model
   read (Factory 80%, agentready weights, Scorecard 0–10) lets a level pass with named failures inside
   it. ❌ Factory/agentready-style maturity levels.
4. ✅ **Candidate = announced, not counted** — the shipped name for principle 11. Cortex "scheduled
   start date", OpsLevel "Enable Later": a check visible in the report but not yet failing anyone.
   Take the mechanism: a `candidate` checkpoint reports its verdict, marked not counted.
5. ✅ **Add `lifecycle: candidate | stable` beside `expires`.** Scorecard ships `experimental|stable`
   per probe. Expiry answers "re-justify by when"; lifecycle answers "does it count now". Two fields,
   two questions.
6. ✅ **`fix` carries `effort` and, where it can, the patch itself.** Scorecard `remediation.effort` +
   per-finding `metadata.patch`; Cortex links the fix workflow; Factory opens the PR. Supports
   principle 15; `effort` orders the fix queue without a score.
7. ✅ **Write gate output for the agent.** Böckeler ("positive kind of prompt injection"), OpenAI
   linters with remediation in the message [S]. A checkpoint on the repo's own gate: a failing custom
   check prints how to fix it. Fits principle 13's goal of moving checks into `make check`.
8. ✅ **The AGENTS.md checkpoint tests content, not presence.** Pass = short map into docs; every line
   is something not derivable from code (Claude Code's "would removing this cause mistakes?"); ~100
   lines is OpenAI's number [S], quote it as such. Factory's "add missing AGENTS.md" fix is the
   anti-pattern: ETH [S] measured generated files lowering success.
9. ✅ **Checkpoint index generated from the checkpoint files** — Scorecard's probes.md is generated
   from `def.yml` with a "do not edit" header. Same as principle 2; this is the precedent.
10. ✅ **Projen-style anti-tamper as a candidate checkpoint for repos with derived files** (shelf's
    `make catalog` READMEs): CI fails if a generated file differs from regeneration. Untested in any
    shelf repo; candidate until one breaks without it.
11. ❌ **Copier-style three-way re-apply of a scaffold.** Blueprint's fixes are applied by the agent per
    checkpoint, and principle 1 has no separate scaffold mode; a template merge would reintroduce a
    second mode and the abort/conflict pain Copier documents. Templates stay as fix content inside a
    checkpoint.
12. Evidence for F1, not a decision: **all three template tools chose a checked-in version pointer**
    (`.copier-answers.yml`, `.cruft.json`, `.projenrc`), and cruft records a *rejected* upstream change
    as a commit. That argues for some in-repo record of "audited against blueprint vX, these overrides".
    Beads-only (my lean in F1) has no equivalent. Put to Fable with this row.
13. untested **`blueprint check-update` equivalent** (cruft check exits 1 when behind): a cheap way to
    know a repo was audited against an older checkpoint set. Depends on 12.
14. ❌ **A rule engine or fact store** (Tech Insights fact retrievers, repolinter engine, agentready CLI).
    repolinter archived 2026-02-06; matches principle 14 and agent-harness's stall.
15. ❌ **Flat checkbox playbook** (MS) as the format: no verify, no n.a., no reason. Usable only as a
    source of candidate checkpoints for the inventory (step 1 of the build order).
16. ✅ **Standards decay by scheduled pass, not by memory.** OpenAI doc-gardening agents and the
    20%-of-Friday manual cost [S]; Claude Code "prune regularly"; Böckeler "add a sensor when an issue
    recurs". Matches principle 12's RECONCILE; adds the trigger "a checkpoint that never fires in N runs
    is a deletion candidate" (Böckeler's open question on silent sensors). N untested.
