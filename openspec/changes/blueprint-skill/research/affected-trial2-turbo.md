## Verdict

NOT YET. Turborepo can fully run the gate green and its hashing is correct and fail-closed, but: (1) it needs three
experimental/future flags, (2) --affected only works with a third flag and still needs hand-listed plugin inputs,
(3) a cold run is 2.6x SLOWER than today's `make check-host` (6m47s vs 2m38s), (4) it wins only on unchanged reruns
(4s vs 76-158s) and on nothing else measured, (5) the coverage floor is not incremental, (6) `make check` leaves
blueprint's gate audits blind. Revisit when the Python flags are gone. A homemade per-package result cache (the round-1
recommendation) buys the same win with no Node and no flags.

## How the setup works (for the record)

- turbo.json: three future flags; `envMode: loose`; `agentGuidance: false`; globalDependencies = uv.lock, pyproject.toml,
  conftest.py, bdd-tags plugin; generic tasks `test` (pytest, dependsOn ^test + shelf#sync), `ruff` (check + format --check,
  per package), `deps` (deptry, per package) via top-level `command` (cwd = package dir); root-only tasks `shelf#test`
  (fitness tests/), `shelf#ruff` (tests tools conftest.py), `shelf#typecheck` (pyrefly), `shelf#spell` (codespell),
  `shelf#guard`, `shelf#preset`, `shelf#blueprint`, `shelf#coverage`, `shelf#sync` (`uv sync --frozen`, cache:false).
- One command: `make check` (shim) or `npm run check`; `npm run check:affected` (adds --affected); `npm run check:all` (adds coverage).
- Fail-closed property comes from uv membership (any packages/<x>/pyproject.toml is a member and gets the generic tasks)
  plus --frozen sync that goes red on an un-locked package. It does not cover: a new pytest plugin package (hand list),
  a package without a `src/` dir (deptry task fails red, fine).
