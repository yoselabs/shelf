# any-gate — changelog

AI-facing only: one line per contract-shape change, arrow notation.

## Unreleased

- `any_gate steps` holds one machine-wide gate slot (`gate_lease.hold`, lease `gate`, `--gate-slots`/`$GATE_SLOTS` default 1, 0 = off): a second gate prints one `gate: waiting for a gate slot, held by ... (pid N, held M min)` line (repeated every 5 min) and waits, at most `--gate-wait`/`$GATE_WAIT` 900 s, then runs anyway and says so. Steps inherit `ANY_GATE_LEASED=1` so a gate inside a gate never waits on its parent. `wait_message(wait, what=)` and `REPEAT_WAIT_NOTICE` moved to `any_gate.gate_lease` (still importable from `any_gate.cli`). (shelf-7aqn)
- Gate output says why (log-driven): `inputs.explain(repo, names, recorded) -> (skips, runs)`; `steps` prints `run NAME: N changed (GLOBS)` / `run NAME: no gate passed this tree | gate definition changed | changed files unknown | declares no inputs | --all` before the steps, and `skipped NAME: none of GLOBS changed` after; `run_and_report(..., why=)`. `any_gate test` ends with `test: ran N of M suite(s), K unchanged since they passed -- Ss`. `inputs.unaffected` unchanged in shape, its text now names the globs.

- 0.6.0: `inputs.declared(repo)` = `.blueprint/step-inputs.toml` (blueprint's defaults) widened by the repo's `gate-inputs.toml`; a `[narrow]` step takes the repo's list alone; a change to the defaults file runs every step; `inputs.DEFAULTS`.

- 0.5.0: SIGTERM/SIGHUP stop every step tree; `Step.stopped` replaces exit 125 as "stopped by the gate"; a crashed step thread is a failed step (70); `GATE_FAIL_FAST`; `inputs.unaffected(repo, names, recorded)` runs everything on an empty change set no gate passed; a step named twice is refused. Contract otherwise unchanged.
- 0.4.0: live failures, `--step-limit`, `--fail-fast`, rename hole closed.
- unreleased (in 0.4.0): the gate prints at most `FAILED_LOG_LINES` (60) lines of a failed step's log, then `... N more lines: `just <step>` prints them all`; the head names the failures.
- 0.3.0: child output read through `Captured.text` (stream-proc 0.13.0); requires `stream-proc>=0.13.0,<1`. Contract unchanged.
- 0.2.0: breaking: `GateState(repo, receipts, env)`, `working_key`, `head_key`, `common_dir` take the environment git runs in (`PRE_COMMIT_TO_REF` is read from it); `run_steps` and `run_and_report` take `env=`; the CLI passes `os.environ`. Git and `vm_stat` calls run through `stream_proc.capture` with a timeout (600s per git call). No receipt or key byte changes.
- unreleased (in 0.2.0): `GateState` computes the tree from a copy of the index that keeps its mtime (a copy stamped now hid a same-size edit made in the entry's own timestamp tick: the wrong tree was recorded, `green` said no).
- unreleased (in 0.2.0): `any-gate test` asks again which suites are left once it holds the slot, so a gate that queued skips what the holder passed meanwhile.
- 0.1.0: `any_gate.steps` (`run_steps(names, *, runner, cwd, terminal) -> Report`, `render`, `run_and_report`) and the verb `python -m any_gate steps [--runner just --step-budget --gate-budget] STEP...` (`GATE_STEP_BUDGET` 60, `GATE_BUDGET` 180, `GATE_NOTICE_FD` for notices); `any_gate.changed` (`base`, `everything`, `changed`, `select(repo, patterns, configs, *, skip, scope)`) and the verb `python -m any_gate changed [--repo --scope --config --not] GLOB...` (NUL-separated paths); `GateState(repo, receipts)` with `start()`, `passed(gate) -> bool`, `green(gate) -> bool` (key `<tree> <base>`, receipt `gate-<gate>`); verbs `python -m any_gate start|passed|pre-push [--repo --receipts --gate] [-- CMD]` (default receipts: `gate-receipts.json` in the git common dir); `python -m any_gate test --receipts FILE [--lease-root --slots --wall --idle --cwd] -- RUNNER...` reads plan lines `unit<TAB>key`, runs `RUNNER UNIT...` for the units without a receipt under a lease and limits, records them when it exits 0; `run_runner(runner, units, *, cwd, wall, idle, on_output) -> RunResult(returncode, stopped)` (the pytest stages are `any-gate-python`'s runner); `workers(tests, Resources, ...)`, `Resources`, `detect()`, `too_wide()`; `key(**parts) -> str` (32 hex, canonical JSON, order-free, refuses non-JSON); `Receipts(path, *, keep=50)` with `has(name, key) -> bool`, `record(name, key)`; file `{"version": 1, "receipts": {name: [keys, newest first]}}`.

- 0.1.1: the receipts file is re-read under the test slot; `nice` for the runner; a too-wide alarm. Contract unchanged.
- 0.4.0: additive  ⇒  `run_steps(..., step_limit=, halt=, on_done=)`, `run_and_report(..., step_limit=, halt=)`, `Report.not_judged`, `STEP_LIMIT=3600`, exit codes 124 (step over its limit, tree stopped) and 125 (stopped by `halt`, never a pass); `steps --step-limit S --fail-fast` (refused with `--all`); a failed step's log is shown the moment it ends, each step runs in its own session (`stream_proc.run`), Ctrl-C stops every tree; `changed.changed()` lists both paths of a move (`--no-renames`); needs stream-proc 0.18  ⇐  0.3.0 showed failures after every step ended, had no step limit, hid the old path of a rename
- 0.7.0: + `steps --opens` (`run_steps(..., opens=Path)`, `run_and_report(..., count_opens=True)`, `any_gate.opens`: `prepare`, `env_for`, `collect`, `lines`, `Opens(step, opens, spawns, pythons)`)  ⇒  after the timing line, per step the Python file opens, process starts and Python processes; opens by non-Python programs and `python -I` are not counted; nothing else changed
