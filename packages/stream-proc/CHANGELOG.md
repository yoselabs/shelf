# stream-proc — changelog

AI-facing only: one line per contract-shape change, arrow notation. No prose, no rationale
(see the ledger for why). Read this before source/README when reconciling a pin
(agent-loop.md WORKFLOW: RECEIVE).

- 0.1.0: new  ⇒  `run(argv, cwd=, env=, on_stdout=, on_stderr=, timeout=, idle=, stop=, grace=, prove=, drain=) -> Result(returncode, signal, timed_out, pid, pgid, start, secs, survivors)`, `stop_tree(p, grace=, prove=) -> tuple[int, ...]`, `alive(pid, start=None)`, `proc_start(pid)`, `TermHold`, `popen_held`
- 0.2.0: additive, no breaking change  ⇒  `group_alive(pgid) -> bool` (`killpg(pgid, 0)`; PermissionError ⇒ True; pgid <= 1 ⇒ False), `table() -> dict[int, Proc]`, `descendants(root, rows=None)`, `Proc(pid, ppid, pgid, sid, start, state, cpu_s=0.0, cmd="")` (two new defaulted fields); macOS path via libproc/ctypes (`stream_proc.procmac`, selector `stream_proc.proctable`): real start token `<sec>.<usec>` for `alive`/`proc_start`, descendant sweep in `stop_tree`  ⇐  v0.1.0 had no start token and no sweep on macOS; Linux behaviour unchanged
- 0.2.1: fix, no contract change  ⇒  `run` closes the child's stdout/stderr/stdin pipes on every exit path (normal, wall, idle, stop, exception) and ends its reader threads first (they poll the pipe, so a grandchild holding it open no longer pins them); no ResourceWarning for unclosed pipes under `-X dev`  ⇐  v0.2.0 left the two pipe objects to the garbage collector
- 0.2.2: fix, no contract change  ⇒  `TermHold`/`popen_held` hold SIGINT as well as SIGTERM, so a Ctrl-C between the fork and the caller's `try` reaches `stop_tree` (KeyboardInterrupt after the child is known) instead of orphaning its tree; a signal held during a spawn that raises is replayed, not dropped; `TermHold.held` is the list of held signal numbers, `TermHold.old` a dict signum → handler  ⇐  v0.2.1 held SIGTERM only and dropped a held signal on a failed spawn
- 0.3.0: additive, no breaking change  ⇒  `capture(argv, cwd=, env=, timeout=, tick=, poll_s=, grace=) -> Captured(exit, out, err, secs, timed_out, survivors)` (exit 124 on timeout, `-signal` when a signal ended it; no output cap), `PidHandle(pid, start=None)` (poll/wait/returncode/args for `stop_tree`), `stop_pid(pid, start=None, grace=, prove=) -> tuple[int, ...]` (stops only while the start token matches; wrong token, gone pid or no process table ⇒ `()` and nothing signalled)  ⇐  v0.2.2 had no captured-text run and no stop for a pid we did not spawn
- 0.4.0: additive, no breaking change  ⇒  `capture_bytes(argv, cwd=, env=, timeout=, input=None, stdin=subprocess.DEVNULL, capture=True, grace=, drain=2.0) -> CapturedBytes(exit, out: bytes, err: bytes, secs, timed_out, survivors)` (exact bytes; `stdin` None/DEVNULL/fd/file, `input` exclusive with it; fed without deadlock, BrokenPipe ignored; waits on the child then reads pipes ≤ `drain` s; timeout ⇒ tree stopped, exit 124, `timed_out`, partial bytes, no exception; `capture=False` ⇒ stdout/stderr inherited, `b""`; always a session leader, no controlling tty); `capture()` now runs on it, text via UTF-8 replace, drain 5 s  ⇐  v0.3.0 had text-only capture, /dev/null stdin only
- 0.4.1: fix, no contract change  ⇒  `capture_bytes`/`capture` build and start their reader/feeder threads together after the held-signal replay, so a raising SIGTERM handler replayed there propagates (child stopped first) instead of `RuntimeError: cannot join thread before it is started`  ⇐  v0.4.0 created the threads before the replay and joined them unstarted
- 0.4.2: fix, no contract change  ⇒  `stop_tree` signals the child and its process group first, then the noted descendants; a shell that `wait`s on a background job no longer sees the job end first and exits 0 (macOS bash 3.2), so a stopped tree reads as signal death (`returncode < 0`)  ⇐  v0.4.1 signalled noted descendants first, and a stopped `sh -c "sleep 30 & wait"` returned 0 on most runs
- 0.4.3: fix, no contract change  ⇒  `run` waits for the child with `p.wait(nap)`, nap 1 ms doubling to 20 ms, and sees an ended child at once  ⇐  v0.4.2 slept a fixed 20 ms between polls, so every child cost at least one 20 ms tick of wall (a loop test of 123 real children: 69 s -> 17 s)
